# 审核规则使用说明

在「设置 → 审核规则」中配置审核规则。使用前应先确认目标数据源及其绑定的规则集。

## 配置范围

- 「全局规则」和 MySQL、PostgreSQL、MongoDB、Redis、Doris 页签编辑的是同一份全局配置；数据库页签只筛选适用规则。
- 数据源未绑定独立规则集时使用全局规则。绑定后使用所选规则集，不与全局规则合并。
- 「自定义规则列表」用于管理独立规则集；「引用数据源」列可用于确认修改影响范围。

## 修改规则

1. 通过数据库页签、分类或规则描述搜索找到规则。
2. 调整开关或参数。数值 0、空字符串是否表示不限或关闭，以该行规则说明为准。
3. 选择规则级别：

   | 级别 | 含义 |
   | --- | --- |
   | 默认 | 使用该规则自带的级别，页面括号显示实际默认值 |
   | 拦截 | 命中该规则时阻止操作 |
   | 提示 | 命中时提示，不因该规则拦截 |
   | 观察 | 继续检查并记录观察结果，不因该规则拦截 |

4. 点击「保存」后再切换页签或离开页面。观察仍会执行检查；要停用可关闭开关。其他拦截规则、权限及审批要求仍然有效。

## 新增并绑定规则集

1. 进入「自定义规则列表」，新增规则集并填写名称、选择类型。MongoDB 数据源建议选择 MongoDB v2。
2. 配置所需规则、参数和级别，点击「保存」。
3. 在「数据源管理」中编辑目标数据源，选择与其类型匹配的规则集并保存。
4. 用目标数据源进行审核，确认规则效果。

规则集支持 JSON 导入和导出。导入时填写名称并选择文件；旧 SQL 规则集还需选择目标数据源类型。系统会校验导入定义，MongoDB 的 DBA 特批规则会被强制启用。

## MongoDB 特批规则

带 DBA 标记的删除集合、重命名集合和账号/权限管理规则强制启用；关闭或降低级别不能绕过 DBA 特批。普通规则仍按各自配置检查，完成特批也不能豁免其他拦截规则。

## 变更历史和停用

- 保存后的全局配置或规则集，可在编辑页打开「变更历史」查看最近 50 条记录。
- 选择历史记录并确认回滚，会撤销所选变更，将当前规则配置恢复为该次变更之前的状态；没有变更前快照的新增记录不能回滚。回滚操作本身也记入历史。这里恢复的是规则配置，数据库数据的恢复需按工单回滚流程处理。
- 要停用某条规则，关闭该规则开关并保存。
- 要删除规则集，在「自定义规则列表」中操作。若有数据源引用，先调整这些数据源的绑定。

## 自定义文本检查

在「自定义审核规则」中填写名称、正则表达式、说明和级别并启用，用于匹配提交的 SQL 文本。正则检查不解析 SQL 语法，建议先用「提示」验证匹配范围，再按需要改为「拦截」。
